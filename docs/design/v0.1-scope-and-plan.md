# Moira v0.1 — Scope & Plan (re-scoped post red-team)

> **Historical.** This is the original v0.1 scoping note. The current architecture
> and runtime are described by the ADRs in [`../adr/`](../adr/README.md) (e.g. the
> custom DAG engine + durable runner superseded the LangGraph plan — see ADR-006).
> Kept for design provenance.

**Date:** 2026-06-04  
**Status:** Active  
**Basis:** DEC-MOIRA-001 (red-team verdict) + owner clarifications  
**Principle:** v0.1 = orchestrator spike = red-team kill-test #3 = first demo. One build, three jobs.

## What v0.1 must prove

> Can Moira's governed orchestration layer drive ONE real FUNC spec end-to-end (analysis → code → tests → review) using pluggable frontier backends, with human gates and a per-step audit record — and what is the unattended completion rate?

If this works on a real Hycom FUNC spec, the core thesis (governed agent orchestration above best-of-breed harnesses) is proven. If it doesn't, we learn the honest architecture before spending on v0.2+.

### What v0.1 sells (honest claims only)
Do **NOT** claim "months to weeks" or "no compliance compromises" at this stage. Sell the measurable, deliverable value:
- **Less rework** — gates + verifiers catch issues before they compound across handoffs.
- **Better audit trail** — per-step audit record (input/output/tools/decisions/approvals/cost/time/owner) + git-native lineage.
- **Faster handoff** — context travels with the artifact; no re-explaining between phases/people.

Speed claims are *measured in the spike* (agent-active vs gate-wait time), never asserted up front.

## Scope by priority

### P0 — Must (this IS the spike + kill-test + demo)

| # | Capability | Notes |
|---|-----------|-------|
| P0-1 | **Orchestration core** | Pipeline as a graph; sequential node execution; state persisted to SQLite; pause / resume / retry. LangGraph as coordinator (ADR-002), execution delegated (ADR-004). |
| P0-2 | **Pluggable agent backend** | Backend interface; first backend = **Claude Code CLI** (frontier, ai-sdlc-compatible). Node declares which backend + model. |
| P0-3 | **AI SDLC repo reader** | Read `INT-`/`REQ-`/`FUNC-`/`ADR-`/standards from the `ai-sdlc` repo as agent context. The repo is the single source of truth. |
| P0-4 | **One end-to-end pipeline** | 1 real FUNC spec → analyze → code (delegated to frontier backend) → tests → review. The vertical slice. |
| P0-5 | **Human quality gate** | Pipeline pauses at gate; human APPROVE / REJECT (→ back to agent with feedback) / MODIFY. CLI or minimal UI acceptable for v0.1. |
| P0-6 | **Audit record** (per step) | input · output · tools used · decisions · approvals · cost · time · owner — plus git-native artifact lineage. Verifiable facts, NOT model-reasoning tracking. *The differentiator that survived red-team.* |
| P0-7 | **Minimal cockpit shell** | Tauri + React: live run status, step log / reasoning viewer, gate approve/reject button. |
| P0-8 | **Cost tracking** | Tokens + $ per step, aggregated per run. |
| P0-9 | **Instrumentation** | Measure agent-active-time vs gate-wait-time; unattended completion rate over N runs. *Feeds kill-test #3 + the "months to weeks" reality check.* |

### P1 — Should (proves model-agnosticism / no lock-in)

| # | Capability | Notes |
|---|-----------|-------|
| P1-1 | **Second agent backend** | OpenAI Codex CLI or direct API via LiteLLM — proves no vendor lock-in. |
| P1-2 | **Local model option** | Ollama via LiteLLM for ONE non-coding node (e.g. classification/summarization) — proves "don't lock in" without betting coding on local. |
| P1-3 | **Retry-then-gate** | Default error handling: retry N times, then auto-escalate to human gate. Configurable per node. |
| P1-4 | **Read-only pipeline viz** | React Flow renders the running graph (read-only). 80% of demo value, 20% of editor work. |

### P2 — Later (v0.1.x / deferred per red-team)

- Visual pipeline **editor** (drag-drop, save to YAML) — demo candy, deferred until we see how pipelines are actually used.
- Multiple parallel agents.
- Guardrail checks as Auto Check nodes.

### Out of scope (v0.2+)

- **Zdzira** — wrap as a library (docs-render / ticket / git-sync modules only), NOT shared-codebase superset (ADR pending). Exclude Confluence/Jira sync, export, skills.rs/ai.rs.
- Client portal + client approval gates.
- Mobile companion (demoted — no moat value per red-team).
- Governance packs (validate via 1 hand-encoded control in the dogfood pilot first).

## Architecture (v0.1)

```
┌─────────────────────────────────────────────────────────┐
│  Tauri Shell (Rust) + React UI                          │
│  · run status · step/reasoning log · gate approve/reject │
└───────────────┬─────────────────────────────────────────┘
                │ IPC (local FastAPI or Tauri commands)
┌───────────────▼─────────────────────────────────────────┐
│  Python orchestration sidecar                           │
│  · LangGraph pipeline (gates = interrupts)              │
│  · SQLite state + cost + provenance                     │
│  · AI SDLC repo reader                                  │
└───────────────┬─────────────────────────────────────────┘
                │ delegates each node to ↓
┌───────────────▼─────────────────────────────────────────┐
│  Execution layer (pluggable)                            │
│  · Claude Code CLI  (P0 — DEV/coding node)              │
│  · LiteLLM → frontier API (analysis/reasoning nodes)    │
│  · LiteLLM → Ollama  (P1 — one non-coding node)         │
│  · OpenAI Codex CLI  (P1 — no lock-in)                  │
└─────────────────────────────────────────────────────────┘
```

## Framing (owner, 2026-06-04)

We are **building a genuinely good solution for software houses** — Hycom is the first/main user at the start, but not hard-locked to "internal only." We are **not** optimizing for build cost or market position at this stage; the question is *"is this great for the job?"*. Business/GTM kill-tests are useful signal but do **not** gate the v0.1 build.

## Success criteria for v0.1

- [ ] One real Hycom FUNC spec driven end-to-end with ≥1 human gate.
- [ ] Git-native provenance trail produced and inspectable.
- [ ] Unattended completion rate measured over ≥10 runs.
- [ ] Agent-active vs gate-wait time decomposed (reality-check the speed claim).
- [ ] Two backends demonstrated (P1) — frontier + one alternative.
